# Browser profile sharing

Confirmed 2026-10-11: recipient name and email must identify the same existing account. Configuration is shared by default; login snapshot is explicit opt-in. Invitations expire from send time (1/7/30 days or custom deadline), require acceptance, and can be declined, withdrawn, left, or have their deadline edited. Recipient receives an independent frozen snapshot; edits never flow back. Received profiles cannot be copied, reshared, exported, or attached to personal cloud sync through NodeCloak. Online authorization gates every launch and is checked every 60 seconds while running, including when the app window is hidden. Warn five minutes before deadline; close on expiry, revocation, logout/account mismatch or authorization failure. Website session revocation itself remains controlled by the website.

Reuse existing VI tokens, Sora/JetBrains Mono, Lucide icons, SelectMenu, Toggle, native dialogs, card/control styling, and Chinese/English translations. Existing Google icon and theme fixes must be preserved. No version/tag/release changes requested.

Authenticated accounts use the existing profile name (`account.name`) as the requested username; email is the unique identifier and both must match. Encrypted snapshots are individually addressed to the recipient’s existing non-revoked logged-in devices, including pending devices. Invitations can be sent before device approval. Recipients explicitly authorize the addressed current device for this grant in an in-place acceptance dialog; personal cloud vault setup is not required. Newly added or unaddressed devices require a fresh invitation. Server stores only opaque ciphertext and HPKE-wrapped random share keys. Cloud metadata contains sender/recipient/profile title/deadline/status, never cookies or credentials. Snapshot config reuses portable Document; optional login reuses validated browser-neutral Snapshot. Owner browser must be closed for a consistent optional login capture.

Contract: `POST /v1/shares/recipient {name,email}` -> `{account:{id,name,email},devices:[{id,publicKey}]}`. `POST /v1/shares {id,sourceProfileId,profileName,browser,recipientId,recipientName,recipientEmail,expiresAt,includesSession,note,payload,writer,envelopes:[{deviceId,publicKey,envelope}]}` -> `{share}`. `GET /v1/shares` -> `{sent,received,serverTime}`. `POST /v1/shares/{id}/accept|decline|revoke|leave` and `PATCH /v1/shares/{id} {expiresAt}` -> `{share}`. `GET /v1/shares/{id}/payload` -> `{share,payload,envelope,writer}` only after acceptance and for an addressed, authorized non-revoked device with the same public key. `POST /v1/shares/{id}/authorize` -> `{share,serverTime}` checks live deadline and account/device access. Accept optionally takes `{authorizeDevice:true}`; consent and the grant transition are atomic. Received list entries include `deviceAccess:ready|authorizationRequired|unavailable`. Share summary fields: `id,sourceProfileId,profileName,browser,senderId,senderName,senderEmail,recipientId,recipientName,recipientEmail,includesSession,note,status,createdAt,expiresAt,acceptedAt`; statuses `pending,accepted,declined,revoked,left,expired`. UUID share IDs; source profile IDs are local identifiers. Lists never return encrypted payloads or envelopes.

Desktop bridge: `sharing_action` accepts tagged actions `{type:'list'}`, `{type:'create',profileId,name,email,expiresAt,includesSession,note}`, `{type:'accept',id,authorizeDevice?:boolean}`, `{type:'decline'|'revoke'|'leave'|'cleanup',id}`, `{type:'extend',id,expiresAt}`; result is direct JSON list/summary with optional `localProfileId` for a ready import and `localDataPresent` for local data requiring cleanup. Native profile views add optional `sharing:{id,senderName,expiresAt,status}`. Global background event `sharing-changed` refreshes metadata/badge/warnings; `profiles-changed` refreshes list. Received local bindings are durable and keyed by account and grant ID; ordinary profiles retain offline use.

Acceptance/import is retryable: reserve a durable restricted local binding before restoring session; authorize again before exposing the imported profile; failed import remains inaccessible and can be retried/cleaned. Terminal grants never reactivate. Enforcement stays native and independent of frontend/personal auto-sync.

Local cleanup is available for terminal grants and failed imports without a server transition or unlocked personal vault. It closes the associated browser, removes this device's imported data, and retains a restricted tombstone. It never changes the friend's original or reactivates a grant. A still-valid accepted grant can subsequently be imported again.

Deadline limits: at most 366 days from the current server time. Service quotas bound individual opaque payloads to 12 MiB and active grants per sender to 1,000 / 256 MiB combined. Terminal records retain metadata; their payloads and wrapped keys are cleared. Snapshot invitations address non-revoked devices present when sent. Migration 7 records nullable per-envelope `authorized_at`; explicit consent authorizes only that device on that grant and never globally approves a personal-cloud device. Existing current-epoch approved devices remain compatible with acceptance without this flag.

Runtime checks use monotonic deadlines derived from server time, a 60-second authorization lease, and a native one-second local watchdog. Network checks normally run every 20 seconds. Failure, expiry, revocation or account mismatch stops the exact received profile process tree after a bounded graceful attempt, including a browser close prompt. A durable received-share profile marker retains restrictions even if its separate binding store is missing.

Updated after user request 2026-10-11: creation and reception are independent of personal cloud sync. Logged-in senders can send immediately; recipients click “接受分享”, confirm the current device with “授权并接受”, and import directly. Cancellation does not grant access or accept the invitation. The sharing flow never opens the personal sync settings panel.
