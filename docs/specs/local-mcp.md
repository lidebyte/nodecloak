# Local MCP and browser automation

Scope: phases one and two, Windows/macOS, Chrome/Edge/Firefox. No remote gateway or cloud-sync tools in this delivery.

The installed NodeCloak executable accepts `--mcp --instance <namespace> --client <grant-id>` before initializing Tauri. It serves stdio through official rmcp and forwards bounded, authenticated requests to the single desktop runtime over loopback TCP. A non-HTTP binary protocol avoids exposing a browser-accessible HTTP endpoint. Each connection authenticates both peers with fresh nonces and role-bound HMAC proofs from the keyring secret before sending tool arguments; request proofs bind the immutable arguments. Stored token hashes cannot generate these proofs. HKDF-SHA256 derives direction-separated session keys; ChaCha20-Poly1305 encrypts and authenticates requests and replies, bound to the handshake nonces. Per-client secrets and endpoint discovery use the OS credential store, with no plaintext credential fallback.

The desktop issues grants explicitly: name, selected profile IDs, expiry, read/manage/page-read/page-write/files permissions, optional exact allowed origins, and interaction confirmation. Newly created profiles join only their creator's grant. Revocation and expiry apply on every request and again before pending jobs execute. Generic profile serialization never crosses MCP; projection omits proxy secrets, credential references and sharing capability data.

Tool groups: status; profiles list/get/create/update/clone/start/stop/trash/restore; proxy diagnostics; fingerprint summary/regeneration; tabs list/open/close; frame listing; page snapshot/screenshot/click/fill/select/scroll/wait; upload, download listing, dialogs; jobs get/cancel. Destructive changes and optional page-write confirmations become desktop approval jobs. Jobs are bounded and owned by client. Cancellation means stop future steps; an already dispatched browser action cannot be undone.

Chrome/Edge reuse CDP, Firefox reuses BiDi. A controlled launch path is required even for legacy/no-regional profiles. Uncontrolled already-running profiles must be restarted by the user. All requests use the existing controller thread, pumping auto-attach events while awaiting replies. Tool errors must not close the browser. Browser queries use isolated worlds/sandboxes; snapshot element references expire on document replacement or next snapshot. Actions recheck destination and frame origins. HTTP/HTTPS and about:blank navigation only. File access requires explicitly selected directories, canonical containment and size limits.

UI: MCP and automation in preferences, Ink/Paper/Phosphor tokens, existing Toggle/SelectMenu and compact outlined/primary controls. Client grants, copy configuration, permission descriptions, approvals, jobs, error retention, revoke and stop actions. Browser content is external data and may be sent to the connected AI client; the grant dialog explains this.

Acceptance: authenticated stdio end-to-end; malformed/oversized requests and unauthorized targets rejected; revoke/expiry/cross-client job access; parameter-bound approvals; per-profile concurrency; actual Chrome/Edge/Firefox page flows including frames/navigation, snapshot invalidation, screenshots, inputs, uploads/downloads and dialogs; stable fingerprint regression; frontend tests/build; native suite and cross-platform CI when available.
