范围：当前工作区的账号、资料编辑、密码/2FA、Google 关联和重新验证、云端配置与登录状态同步、冲突与设备授权、浏览器副本、终端、更新及退出。以下四项是初次只读复审的发现；后续修复和验证记录见文末。

初次复审结论：存在一个数据安全 P1、两个流程 P2，以及一个线上部署阻断项。

## 1. P1：删除与修改冲突没有冻结对应登录状态

位置：`src-tauri/src/cloud/session_sync.rs:295`，关联 `sync.rs:495`、`sync.rs:575`。

场景：A/B 已同步相同副本和网站登录状态。B 仅修改副本名称或备注；A 删除副本并同步配置与登录快照 tombstone。B 同步时，配置保留本地副本并产生 `deletion_vs_edit`，但会话同步仍独立运行。其本地登录快照未变化，因此会把云端空快照导入，清除 Cookies、LocalStorage 和 IndexedDB。之后在配置冲突中选择保留本地或两份，无法保留原登录状态。

依据：配置冲突只记录、不终止此副本的会话应用；会话运行只检查已提交配置基线是否删除，不检查待处理配置冲突。空快照应用后会更新登录快照基线，正常缓存清理还会移除旧版本。

建议：对删除/恢复相关配置冲突冻结该副本的登录状态应用、删除及发布，待用户明确选择后协调处理配置与登录数据。补充跨配置/会话的双设备集成回归。此次依据代码控制流确认，未在真实网站登录数据上触发破坏性复现。

## 2. P2：切换页面后 Google 重新验证无法继续

位置：`src/AccountWorkspace.tsx:93`，关联 `src/App.tsx:205`、`server/internal/api/google.go:156`。

场景：需要重新验证身份的 Google 用户在个人资料页点击重新验证，切换到副本列表，再完成外部浏览器 Google 验证并返回。inline AccountDialog 卸载会停止轮询、丢失 googlePending；常驻 modal 是独立实例，不能接续这次验证。服务器只在 googlePoll 消费流程时更新当前会话 auth_at，普通状态刷新不能完成验证，因此首次设置密码仍被 recentAuth 阻挡。

建议：将 pending 状态、轮询与完成处理提升到常驻 useCloudAccount，跨页面共享；为切页、返回和超时场景补充交互测试。

此次通过现有 SSH 连接只读检查运行中的服务进程，输出配置存在与否，未输出任何密钥或邮箱。结果：服务运行中、Google 配置存在，SMTP_HOST、SMTP_USERNAME、SMTP_PASSWORD、SMTP_FROM 均未配置。

## 4. P2：首次同步没有直接选择暂不同步的入口

位置：`src/AccountWorkspace.tsx:128`，关联 `src-tauri/src/cloud/sync.rs:292`。

新账号或未授权设备的同步面板先强制进入建立加密空间、设备授权及恢复密钥确认。只有完成这些步骤，才会显示包含“暂不同步”的方式选择。后端 none 已允许跳过解密和密钥确认，前端没有提供对应入口。

默认自动同步关闭，用户关闭面板也不会开始同步；这里的问题是明确选择并保存“暂不同步”的流程不可达，而非默认擅自上传。

建议：加密空间门控之前提供直接跳过同步动作，再仅对上传/合并执行授权和恢复密钥前置条件。

## SMTP 配置和送达复验（同日后续）

用户提供了邮件服务凭据。`mail.nodecloak.com` 在公共及权威 DNS 中均返回 NXDOMAIN；`nodecloak.com` 的 MX 指向 `mail.nodeloc.com`。使用这个实际邮件主机通过有效证书校验、587 STARTTLS（TLS 1.3）和邮箱认证后，将 SMTP_HOST、SMTP_PORT、SMTP_USERNAME、SMTP_PASSWORD、SMTP_FROM 原子写入现有服务器配置，保留其他配置。文件仍由 root 所有且权限为 0600，重启后逐项核对运行进程已加载，健康检查通过；凭据未写入仓库或输出日志。

本地开发机器调用公网验证码接口返回 202。另一次服务器 loopback 请求返回 202，并通过只读 IMAP 在所提供的发件邮箱内确认对应验证码邮件送达，仅检查邮件头，没有输出验证码、兑换验证码或创建测试用户。生产主机请求自身公网地址返回非 JSON 403，因此该路径未作为应用发信失败的依据。真实邮箱登录及 2FA 邮箱登录仍需交互验收。当前 SMTP_HOST 使用 `mail.nodeloc.com`；改用 `mail.nodecloak.com` 前需先配置 DNS 和匹配证书。
