# MCP phase three: synchronization and remote access

Scope: add scoped sync previews/runs/conflict decisions and a standard Streamable HTTP MCP gateway to the existing Go/PostgreSQL account service. Chrome, Edge and Firefox use the same desktop broker. Preserve existing local STDIO grants, all fingerprint behavior, and the NodeCloak Ink/Paper/Phosphor VI. No release, deployment or hibernation is part of this request.

Remote OAuth clients register exact HTTPS or loopback redirect URIs. Authorization requires S256 PKCE, resource audience `/mcp`, bounded scope selection, state round-trip, and explicit consent in the signed-in approved desktop device. The authorization browser displays a short one-time pairing code; the desktop retrieves the request and creates a separate local grant scoped to selected profiles, websites, files and expiry. Account/Google tokens never serve as MCP access tokens. Access tokens are short-lived; refresh tokens rotate, reuse revokes their grant. Discovery publishes protected-resource and authorization-server metadata.

The device polls authenticated `/v1/mcp/relay` endpoints with its account session, publishing only its explicitly approved routes. Every remote call is revalidated by the local grant and existing broker. Routes bind account, approved device, OAuth client and dedicated local grant. Device logout/revocation, grant expiry/revocation and disabling MCP stop execution. No inbound desktop HTTP port or public CDP/BiDi endpoint is added.

Gateway job delivery is at most once. PostgreSQL atomically marks a queued request dispatched before sending it. Dispatched requests are never replayed after reconnect. Device receipts are persisted before invoking the broker; a duplicate delivery without a recorded local job fails as indeterminate rather than repeating a click. Idempotency binds MCP session + request ID + immutable tool arguments. Offline/expired requests fail before execution. Cancellation prevents future steps and propagates to local jobs. Browser operations already dispatched cannot be undone.

Gateway arguments/results are encrypted at rest with domain-separated authenticated encryption, expire after 15 minutes, and are never written into logs. A background cleanup erases expired payloads on the next healthy one-minute tick; database backup retention is configured separately. Long-lived records contain identifiers and states only. Authorized page text/screenshots necessarily transit the MCP gateway to the remote AI client; disclose this before consent. Browser-session ciphertext is decrypted only on the desktop; raw cookies, account tokens, vault/recovery keys and proxy secrets are never exposed as tools.

Sync tools require explicit `sync` permission and selected authorized local profile IDs. Preview exposes metadata/actions/conflicts, not decrypted configurations or website-session data. The preview fingerprint binds account, client, local profile versions, binding state and cloud revisions. Run requires the unchanged fingerprint and only synchronizes selected bound profiles; it never attaches unrelated profiles or automatically pulls new cloud profiles. Conflict resolution additionally requires desktop approval and an unchanged preview. Keep existing lease fencing, close-browser checks, rollback detection, account/profile isolation and recovery-key guards. Cancellation is checked between profile operations.

Acceptance: OAuth PKCE/audience/redirect/replay/refresh reuse tests; PostgreSQL queue ownership, at-most-once delivery, expiry, revocation, cancellation and encrypted payload tests; local sync schema/permission/filter/preview invalidation tests; VI UI tests; desktop-to-gateway test with three real browser backends where available. All existing frontend/native/server tests and builds must remain green. Document unverified platforms honestly.

References: https://modelcontextprotocol.io/specification/2025-11-25/basic/authorization and https://modelcontextprotocol.io/specification/2025-11-25/basic/transports.
