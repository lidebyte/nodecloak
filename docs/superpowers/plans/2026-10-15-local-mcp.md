# Local MCP Implementation Plan

> **For agentic workers:** Execute task-by-task with test-first verification and independent review. Reviewers may inspect isolated components; root owns implementation.

**Goal:** Let authorized local AI clients manage and operate NodeCloak profiles across three browsers.
**Architecture:** rmcp stdio adapter -> authenticated loopback broker -> shared profile commands/controller. Keyring-backed grants, bounded approval jobs, isolated browser snapshots.
**Tech Stack:** Rust/Tokio/rmcp, Tauri, React/TypeScript, existing CDP and BiDi.
**Spec:** docs/specs/local-mcp.md

## Global constraints

All three browsers; Windows and macOS; existing VI; sensitive values omitted; no remote gateway; do not publish or bump release until requested.

## Tasks

- [x] Grant policy and schemas: create `src-tauri/src/mcp/{mod,policy,catalog}.rs`; test denied permissions, expiry, exact-origin checks and secret-free projections before implementation. Use stable IDs, strict bounded parameters and tool-specific permissions.
- [x] Local broker and stdio: create `mcp/{broker,stdio}.rs`, modify Cargo.toml/main.rs/lib.rs. Test actual authenticated framed IPC, malformed requests and per-client ownership. Store tokens only in OS keyring; configure existing executable's stdio mode.
- [x] Environment tools: create `mcp/operations.rs`, share guarded profile commands, add explicit controlled-launch option. Test create/clone seed isolation, permission denial and deletion approval.
- [x] Browser tools: add `browser_control/automation.rs` and `mcp/page.js`; extend controller requests. Test snapshots and stale element rejection first; run real fixtures on Chrome/Edge/Firefox for navigation, frames, inputs, screenshots, upload/download and dialogs. Pump paused targets while waiting.
- [x] VI workspace: create `src/{McpWorkspace.tsx,mcp.ts,mcp.css}` and UI tests; integrate preferences and bilingual copy. Test grant form, selection, revoke, copy config and approval decisions.
- [x] Verify: frontend test/build, native suite, stdio smoke and three-browser fixture; independent security/lifecycle review and fixes. Document configuration, capabilities and validation evidence in `docs/specs/local-mcp-validation.md`.

## Validation scope

Windows native Chrome, Edge and Firefox and the real desktop/stdio chain were exercised with synthetic profiles. macOS uses the shared implementation and existing CI matrix; runtime verification on a Mac remains a release gate. No release version, published binaries or production user profiles were changed.
