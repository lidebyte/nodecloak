# NodeCloak 2.2.0 Release Plan

**Goal:** Publish the completed browser enhancements as 2.2.0 for Windows x64 and macOS Apple Silicon/Intel, update GitHub and the production website, verify final downloads, then hibernate this computer.

**Architecture:** Use the existing tagged GitHub Actions builds, macOS signing/notarization and signed updater workflow. Keep the release draft until complete assets, package identities, checksums and signatures are verified. Deploy the website atomically through its existing release procedure. Preserve existing profiles, server configuration and past release directories.

**Files:** Version fields in package.json/package-lock.json/src-tauri/Cargo.toml/Cargo.lock/tauri.conf.json; user-facing notes in scripts/prepare-release.mjs; fingerprint fixture step in .github/workflows/build.yml; website package metadata and website/release-notes.json; internal evidence in docs/releases/2.2.0.md.

- [x] Set every desktop version to 2.2.0 and write bilingual user-facing notes. Run version, frontend, native, fingerprint, session codec, release and Apple-ticket checks, plus the production build and diff checks.
- [x] Commit and push the reviewed changes, create immutable v2.2.0, and run all three platform jobs. Confirm complete successful Windows and notarized macOS artifacts before publication.
- [x] Collect assets in a fresh private staging directory, apply the existing Windows signing procedure, request updater signing, verify all package versions/architectures/signatures and recompute release checksums. Verify the draft GitHub asset digests.
- [x] Publish the verified GitHub release. Update the website version/notes/manifest from that release, verify local website checks and four download hashes, commit and push website changes, deploy to a new immutable release root and atomically switch current.
- [x] Download and verify public packages/manifests, check latest/update URLs and production API readiness, and write/push internal release evidence.
- [x] Only after every release and deployment verification passes, hibernate the computer as explicitly requested by the user. A build or deployment failure leaves it awake for recovery.
