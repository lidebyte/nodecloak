# NodeCloak 3.2.3 release

**Goal:** Publish the independent sync workspace and saved browser-page recovery on Windows x64 installer/portable and macOS Apple Silicon/Intel; align GitHub, website and in-app updates.

**Constraints:** Preserve user profiles and running installed app. Public notes describe user behavior and relevant recovery limits. Follow existing Windows package and updater verification. Keep account-service binary, database and private config unchanged. Do not shut down the computer.

- [x] Align version and bilingual notes; pass frontend, Rust, script and native regression checks; review release candidate.
- [x] Commit/push exact source and tag; pass the three-platform build matrix.
- [x] Verify original assets, finalize Windows packages and updater, check versions, package contents, signatures and hashes.
- [x] Publish GitHub; update/test/push website and atomically deploy its static files.
- [x] Verify public downloads on both domains and all in-app updaters; compare unchanged service baseline and record evidence.

Engineering evidence is retained privately under `.qa/release-3.2.3/`. Native session recovery and sync behavior are documented in the two preceding feature plans.

## Local preflight

212 frontend tests, 299 Rust tests, 37 script checks, production build and diff checks passed. Protected Chrome/Edge native recovery (including delayed Edge resume) and all three Firefox native restart checks passed. Read-only release and website reviews found no remaining blockers.

The initial high-concurrency Rust run missed a mock-server request; the full suite passed with four test threads without changing product assertions. A deliberately headless Windows Firefox run could not receive window-close messages; native Firefox recovery was rerun as a normal window and passed. CI uses normal browser windows for saved-page checks; protocol-only background checks retain their existing headless setup. Original failed logs remain private alongside the final evidence.

Cross-platform candidate checks also exposed the platform temp symlink in new unit fixtures and legacy Firefox tests assuming Start always requests an edited startup URL. Fixtures now use canonical temp roots and an explicit test-only destination, retaining all existing assertions. A native Chromium restart now waits for profile locks as well as processes. Controlled macOS Chrome uses protected URL recovery because the native window-reopen accelerator was not reliable in CI; release copy states the resulting draft/scroll scope. Failed candidate logs are retained privately and only a complete final matrix may publish.
