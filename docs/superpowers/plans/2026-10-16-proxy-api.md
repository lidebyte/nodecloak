# API proxy extraction implementation plan

> **For agentic workers:** Use executing-plans task-by-task and verify each deliverable.

**Goal:** Optional per-profile HTTP(S) provider API returning strict IP:port text; any other response is an extraction error.

**Architecture:** Keep protocol HTTP/HTTPS/SOCKS5 and local chain as existing settings. Add optional apiUrl source; resolve exactly once before starting a relay/test, strictly validate every nonblank response line, select the first endpoint. Persist the active endpoint separately from configured source so app recovery and running-profile tests use the same IP; a fresh launch fetches again. API requests use the configured local first hop when present, otherwise the computer network without inheriting the unresolved profile proxy. No automatic fallback.

**Tech Stack:** Rust/Tokio/reqwest, existing relay, React VI SelectMenu/Toggle.

**Spec:** This document contains the user requirement and concrete response/lifetime policy.

## Constraints

- Plain UTF-8 IP:port list, CRLF/LF supported, blank lines allowed, IPv6 requires brackets. Every nonblank line must be valid. Empty/error/HTML/JSON-success-like bodies are rejected, including HTTP200 errors.
- Request timeout 10s, body limit 64KiB, no automatic redirects, TLS verification intact. Errors contain no full API URL or known query credentials; safe bounded provider error text is shown.
- No request on save/copy/export. Fresh launch and draft connection test fetch once each; live relay/recovery retains the active IP, and recovery without a saved endpoint returns restart guidance.
- Static proxy behavior, credential binding and existing local chain retained. API URL changes do not reuse a previous authentication destination's password.
- Cloud schema5 preserves API source and rejects it in older schemas; MCP omits API URL/query from profile projection.
- Preserve existing uncommitted popup/sync/chain/import fixes and real user profiles. No release/commit/deployment requested.
