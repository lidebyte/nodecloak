# NodeCloak 3.1.5 release plan

**Goal:** Publish the validated Firefox fingerprint, regional setup and startup fixes to GitHub, the website and the in-app updater.

**Architecture:** Use the tagged Windows/macOS matrix, verify its draft packages, apply the existing Windows signing procedure and updater signature, then publish and atomically switch the website root.

**Constraints:** Preserve existing profiles, credentials and login data. No account-service deployment is needed. Public notes describe user-visible behavior only under AGENTS.md. Preserve the updater key and use the previously authorized platform credentials. No shutdown or hibernation. VLESS/VMess are not implemented or included in the notes.

## Evidence already established

  canonicalize new test fixture paths on macOS without changing production path
  guards; normalize Windows native-host manifest paths so debug and installed
  app spellings of the same directory do not appear to be foreign registrations.
  The path-spelling regression was observed failing before the correction and
  passing afterward; distinct and relative registrations remain rejected.
- The new macOS browser check exposed a test-fixture HTTP bug: an idle or
  incomplete connection received generic executable HTML before any complete
  request. The isolated socket regression was red before fixing the fixture
  and green afterward. Incomplete connections now close without a response;
  unknown resources receive 404. No product behavior changed for this follow-up.
- Hosted macOS headless runs have no interactive Location Services grant. The
  disposable fixture disables the unavailable OS settings prompt using Mozilla's
  documented geo.prompt.open_system_prefs preference. Exact native coordinates
  must be delivered in both main document and iframe; Permissions API labels
  are recorded separately. Product OS policy is unchanged. Native checks
  run before slow packaging and again against the final release executable.
- Native macOS repetition exposed a shutdown race: the main-PID snapshot can
  become empty while a helper still owns the profile. Closing now polls the
  complete closed state within the existing deadline, preserving the concrete
  timeout error. Extension setup uses the same wait before restoring files.
  A real Windows parent-lock drain regression failed before this correction
  and passed after it; it uses only a synthetic temporary directory.
- Intel native setup twice acknowledged shutdown but stayed occupied beyond
  ten seconds. Setup now closes its Marionette transport before a bounded
  thirty-second passive full-state wait, without treating force-kill as success.
  An actual TCP peer holding a temporary parent.lock reproduced the ordering
  failure before transport release and passed afterward. Full Rust regression:
  265 passed / 36 ignored; independent review found no blocker. This establishes
  transport ordering, not proof of the exact remaining Intel process.

- Actual user's test5 with stable fingerprint and custom timezone now starts; local diagnostic stages confirm protection accepted and destination released in about 3.2 seconds.
