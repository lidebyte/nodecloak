Deployed on 2026-10-11 to the existing website host, using systemd and its existing PostgreSQL installation. The public API origin is `https://nodecloak.com`; routes under `/v1/` are forwarded to the loopback listener `127.0.0.1:8088`. `api.nodecloak.com` has no DNS record and is not used by the default desktop configuration.

- Executable: `/opt/nodecloak-account/current/server`, symlinked to an immutable release directory.
- Service: `nodecloak-account.service`, runs as dedicated `nodecloak-account` system user with filesystem/home/device restrictions and no capabilities.
- Configuration: `/etc/nodecloak/account.env`, root-owned mode `0600`, loaded by systemd. Contains real Google OAuth and SMTP credentials and independently generated database password/token pepper. No real credentials are stored in repository files.
- Database and role: `nodecloak_account`, isolated from the other applications' databases.
- Nginx: `/etc/nginx/snippets/nodecloak-account.conf`, included by the existing website configuration. Callback query logging is disabled. Cloudflare ranges were fetched from its official HTTPS lists for the API-only real-IP snippet; Go trusts only the Nginx loopback peer.
- Google callback: `https://nodecloak.com/v1/auth/google/callback`. Register this exact authorized redirect URI in the Google web OAuth client configuration.

The callback returns a centered NodeCloak branded HTML page for success, cancellation and expired links. Its font is embedded, and its CSP permits only the exact hashed stylesheet and embedded font. The callback location forwards that CSP without inheriting the website's second CSP; preserve the location-specific security headers in `nginx-account.conf` when redeploying.

Verified: systemd active, both Google variables loaded by the running process, root ownership/0600 permissions, Nginx configuration validation and reload, and public HTTPS `/healthz` returning 200 with database readiness. Google sign-in was subsequently exercised by the user.

Build a Linux amd64 executable with `CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build -trimpath -o server ./cmd/nodecloak-server`, upload to a new release directory, switch `current`, then restart the service and check readiness.
